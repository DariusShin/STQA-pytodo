# Consolidated Defect Log

One shared ID series (`DEF-001` onward) across Weeks 1-6, using the 12 fields of the course defect template. Week 5 (security and performance, run 25 Nov 2026) added `DEF-024` to `DEF-037`.

- **Severity** (W4 scale, used for 13 defects and applied to W3): `Critical` = data loss, or a user loses access to their own data; `Major` = account integrity broken, a server error on ordinary input, or (W3) a task cannot be completed with assistive technology; `Moderate` = wrong behaviour, a misleading result, a task that is materially harder, or a crash on unusual input; `Minor` = wrong status code, documentation mismatch, or cosmetic/low consequence. W5 rated unauthorised access to other users' data (`DEF-028`, `DEF-029`) as `Critical`; the scale as written does not name confidentiality, so the wording needs group confirmation (Section 3).
- **Priority:** `High` / `Medium` / `Low`, by likelihood and visibility.
- **Status rule (one rule for all):** `Open` = reported once. `Confirmed` = reproduced twice (a second run or a second phase). `Retest` = a fix is claimed and awaits retesting. `Closed` = retest passed. The application is frozen for assessment, so `Retest` and `Closed` are not expected.
- Reproductions of an existing defect in a later phase are added to its Evidence and are not counted as new defects.
