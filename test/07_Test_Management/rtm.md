# Master Requirements Traceability Matrix (RTM)

One row per requirement. Column order follows the course RTM template: Requirement/Feature, Test Scenario, Test Case ID(s) (split by week), Test Type/Technique, Result, Defect ID.

- Weeks 3 and 5 are merged. W5 (`05_Security_Performance`) case IDs are `SEC-nn` (security) and `PERF-nn` (performance); sub-cases `SEC-07a`/`07b` and `SEC-09a`/`09b` are listed under their parent.
- `Result` is Fail if any linked case failed, and covers W1-W6. Usability cases `TC-USA-001` to `005` are Not Run and do not change a result.
- Full case records are in [master_test_cases.md](master_test_cases.md).

## Notes

1. **W3 mapping.** W3 cases name a requirement or a WCAG criterion. Accessibility cases were mapped to requirements through the affected-feature field of their defect (for example `DEF-007` covers REQ-001 to 003 and REQ-005; `DEF-008` covers REQ-004). Compatibility cases run on six configurations (C01-C06); `TC-CMP-007` fails on C02 and C03 only.
2. **REQ-002 now Fail.** The W1/W4/W6 functional checks all pass; the Fail comes from W3 (`DEF-004` navigation at narrow widths; `DEF-007` unlabelled login fields; `DEF-011` unannounced errors). The functional result is Pass.
3. **REQ-004 Fail.** `DEF-020` (the text `"false"` marks a task done) fails `TC-API-036c`. W4 lists `TC-API-036` under REQ-003 and REQ-009; `TC-API-036c` is added here to REQ-004 because the `DEF-020` record names REQ-004.
4. **REQ-006 / REQ-007.** `TC-API-019` and `TC-WEB-011` (bad due date) include dashboard checks, so they appear under REQ-007 as well (`DEF-015`).
5. **REQ-009 (W4):** 14 cases. No W6 automated test exists for it.
6. **W2 mapping** was made by the Defect & Metrics Coordinator from the function each test exercises and needs the W2 author's sign-off.
7. **W6 regression gap.** W6 ran on 2026-11-20, before W4's failing cases were executed (2026-11-24), so `DEF-014` to `DEF-023` are not in the W6 regression suite. The top candidates are `DEF-014`, `DEF-015` and `DEF-023`. W5's `test_security.py` guards some of them (`SEC-18`, `SEC-24`, `SEC-07a`, `SEC-03`).
8. **W5 mapping.** The W5 report maps cases to threats (`TH-nn`), not to requirements. The mapping above was made by the Defect & Metrics Coordinator from the feature each case exercises and needs the W5 author's sign-off. `SEC-03` is placed under `REQ-009` because `DEF-023` names it; `SEC-09a` (login form) appears under `REQ-002` and `REQ-003`.
9. **REQ-004.** No W5 case targets complete/reopen (the CSRF test deleted a task; it did not toggle one), so its W5 cell is `none`.
10. **REQ-008 in W5.** Reading (`SEC-15`) and editing (`SEC-19`) another user's task are refused and `SEC-10` (mass assignment) passes; `SEC-18` (delete, `DEF-014`), `SEC-07b` (search injection, `DEF-029`) and `SEC-20` (forged session, `DEF-028`) fail.
11. **Performance.** `PERF-01` to `06` pass; `PERF-07` fails (`DEF-037`). They run against the endpoints behind `REQ-003`, `REQ-005` and `REQ-007`, so they are shown on the cross-cutting row and, for the dashboard and task list, on `REQ-003` and `REQ-007`.
